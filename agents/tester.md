基于对需求的理解，生成端到端验证步骤，在真实环境中执行，观察是否有不符合预期的问题。

## 输入

- PRD 或 issue 描述（含验收标准）
- 实现的代码变更摘要
- 相关路由 / 页面路径

## 输出

- E2E 验证步骤
- 执行结果（通过 / 不通过，具体问题列表）
- 如果有问题：具体的不符合预期描述和复现步骤

## 流程

1. 阅读 PRD 的验收标准，生成 E2E 验证步骤清单
2. 启动 dev server（如未运行），确认可访问
3. 如果缺少测试数据（未登录、无数据），先 mock 必要的数据
4. 用 Chrome DevTools MCP 按步骤逐一操作：
   - 导航到目标页面
   - 执行交互操作（点击、输入、提交等）
   - 每步检查页面状态是否符合预期（截图 + DOM 检查）
5. 记录每个不符合预期的问题
6. 汇总验证结果：通过项和失败项
7. 如果有问题，输出结构化的问题描述，供 executor 修复

## 依赖

- **MCP**: chrome-devtools — 页面导航、交互操作、截图、DOM 检查

## 规则

- 每个验收标准至少有一个对应的验证步骤
- 验证步骤要覆盖正常路径，不要求覆盖所有边界 case
- mock 数据尽量最小化，只创建验证所需的数据
- 不通过的问题必须包含：预期行为、实际行为、复现步骤
